# RAG 文档处理与问答链路

RAG 服务将企业文档转为可检索的结构化 Chunk，并在用户可见范围内检索、排序和生成答案。目标是同时保证召回质量、上下文完整性、来源可追溯和数据权限安全。

## 文档处理链路

```text
读取 MinIO 原始文件
  → 按文件类型解析为结构化 Block
  → 格式感知清洗
  → 按结构和类型分块
  → 拼接标题与章节元数据
  → 生成 Embedding
  → 写入版本化向量集合
  → 切换活动版本
```

### 结构化解析

解析结果保留正文之外的定位信息：

- Word：按正文顺序处理段落和表格，识别 Heading 层级；
- PDF：保留页码并清理页内文本；
- PPT：优先保持整页内容，记录 Slide；
- Excel：记录 Sheet，表格按表头和行窗口处理；
- 通用元数据：文档 ID、知识库 ID、标题、章节路径、块类型、版本和可见范围。

无法提取有效文本时返回 `NO_EXTRACTABLE_TEXT`，扫描件或空文件不会被标记为成功。扫描 PDF 如需支持，应接入 OCR 后再进入同一清洗和分块流程。

### 格式感知清洗

`DocumentCleaner` 根据块类型清理噪声，而不是对所有文件做无差别字符串替换：

- 去除 HTML 标签、控制字符、重复空白和无意义占位符；
- 保留 Markdown 表格、标题层级、列表和必要换行；
- 规范特殊字符，避免破坏代码、数值和表格边界；
- 保留用于过滤和引用的时间、分类、页码、Sheet、Slide 等元数据。

### 分块策略

| 内容类型 | 处理方式 |
| --- | --- |
| 普通正文 | 约 500～800 字符，优先按章节和自然段边界切分 |
| 表格 | 表头与若干数据行组成一个 Chunk，每块重复表头 |
| PPT | 优先保持整页，超长页面再细分 |
| Excel | 按行窗口切分，每块重复列名 |
| 超长结构块 | 使用约 80～120 字符重叠，普通块不滥用重叠 |

Embedding 输入会加入文档标题和章节路径，提升“简称、章节名、局部概念”等短问题的命中率。向量库同时保存原始 Chunk 和定位元数据，展示引用时不需要从答案正文中反向解析来源。

## 在线问答链路

```text
用户问题与最近对话
  → Query Rewrite
  → 查询向量化
  → 可见文档范围内召回候选
  → 相邻 Chunk 去重与 MMR 多样性排序
  → 相关性过滤与多样性重排
  → 多知识库全局合并排序
  → 按完整 Chunk 构建上下文
  → LLM 流式生成
  → 正文与引用来源分离返回
```

### 查询改写

多轮对话使用有限滑动窗口提供最近上下文。改写器把省略主语、代词或追问补全为可独立检索的问题，同时保留原始问题用于最终回答，避免把历史对话无限拼入检索和 Prompt。

### 召回与排序

- 查询向量化后先召回约 20～30 个候选，而不是过早只取少量结果。
- 所有召回都带可见文档 ID 过滤，权限校验在检索入口生效。
- 相邻或高度重复 Chunk 先去重，减少同一段内容占满上下文。
- MMR 平衡相关性和多样性，避免结果全部来自一个局部章节。
- 当前实现使用相似度阈值、相邻块去重和 MMR 完成轻量重排，不依赖独立重排模型；如需进一步提升精排效果，可在候选集上扩展 Cross-Encoder 或第三方 Rerank 服务。
- 多知识库结果保留统一分数并全局合并，最终选取约 5～8 个高质量 Chunk。

### 上下文与生成

上下文预算按完整 Chunk 计算，不从字符中间硬截断。系统提示要求模型只依据给定材料回答；证据不足时明确说明，而不是补造事实。

生成采用 SSE 流式返回：

- `session`：会话和消息标识；
- `token`：增量回答内容；
- `sources`：结构化引用；
- `done`：正常结束；
- `error`：安全错误信息。

引用来源与回答正文分离，前端在回答结束后单独展示文档名、页码或章节。这样既避免提示词生成的“【来源】”混入正文，也便于后续打开原文定位。

## 质量与性能观察

建议持续记录以下耗时与质量指标：

- 文档解析、分块、Embedding 和向量写入耗时；
- Query Rewrite、检索、Rerank、首 Token 和总生成耗时；
- 候选数量、去重后数量、最终引用数量和相似度分布；
- 无召回率、用户重问率、引用点击率和失败重试率。

当问答变慢时，应先区分检索耗时和模型首 Token 耗时：前者通常与 Embedding、向量库或候选规模有关，后者通常受模型服务、上下文长度和网络影响。
